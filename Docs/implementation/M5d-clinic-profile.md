## Behaviour change

**1. A Clinic profile screen** (*Settings → Clinic profile*, or the *Clinic profile* button on *Clinics*). It has:
- the name, tagline and address, **in English and in Arabic**;
- two phones and an email;
- a licence or registration line.

The English name, the English address and one phone are required. Phones may use digits, spaces, dashes and a leading `+`. The email is optional but must look like an email address.

Who can edit it: whoever manages clinics (*Settings.Clinics*): Admin and Clinic admin.

**2. Printouts use it.**
- **Prescriptions:** the header shows each line in English and, when filled in, in Arabic. The licence line prints at the foot.
- **Lab request slips:** they now show the clinic's name, address and phones under the logo. Before, they showed only the logo.

**3. Until the profile is first saved**, the screen and the printouts start from the `ClinicInfo` server setting, as today. A notice on the screen says it hasn't been saved yet. Once saved, `ClinicInfo` is no longer used. Changing the details no longer needs a redeploy.

**4. The readiness page** (*System → Readiness*) checks the saved profile instead of `ClinicInfo`. It points to *Settings → Clinic profile* when values are missing or still the examples. **One small change:** an empty email no longer counts as missing, since the profile makes it optional.

**5. Each save is recorded** in the audit log (`ClinicProfile.Saved`).

**6. In Arabic and English** (+17 translations).

## Database

One new table, `ClinicProfiles`, holding at most one row (the service keeps it to one):
- `NameEn` (required, 150);
- `NameAr` (150);
- `TaglineEn` and `TaglineAr` (200 each);
- `AddressEn` and `AddressAr` (300 each);
- `Phone` and `SecondPhone` (30 each);
- `Email` (150);
- `LicenceLine` (200);
- the usual created and updated columns.

No foreign keys, and no existing table changes.

The migration is generated by the script as `ClinicProfile`, and it should contain only `CreateTable ClinicProfiles`.

**The live site:** this migration joins the ones still waiting for the idempotent script before the next publish (P8a, P9a, M4d, M5d).

## Unchanged

- The logo, the paper sizes and designs, and the bilingual headings of the printouts.
- `ClinicInfo` stays in `appsettings.json` as the starting values.

  - the Arabic fields, email and licence are optional.
- **1 new readiness test:** an empty email is fine.
- **The access baseline:** the screen's two actions are added (Admin, Clinic admin).
